# 产品需求文档：生活秘书

> **版本** V2.0 | **定位** 有家庭记忆的 AI 代理人 | **更新** 2026-02-10

---

## 一、产品愿景

### 1.1 一句话定义

**生活秘书是一个"有家庭记忆的 AI 代理人"——通过 App + 随身硬件，帮助忙碌的职场人把碎片化的承诺和家人的需求，转化成实实在在的行动。**

> *你负责打拼，我负责守护。*

### 1.2 核心问题

职场人的困境：身在外，心在家，力不从心。

| 痛点 | 具体表现 | 频率 |
|------|----------|------|
| **忘记承诺** | 随口答应的事转头就忘，高铁上想起"下次去北京要见老同学" | 每周 3-5 次 |
| **无暇顾家** | 知道妈妈生日快到了但没时间准备，孩子兴趣班时间记不清 | 每月多次 |
| **人情负担** | 同事帮了忙不知如何答谢，节日送礼绞尽脑汁 | 季度性高峰 |
| **琐事堆积** | 净水器换滤芯、车险续保、体检预约……小事变心理负担 | 持续性焦虑 |
| **信息碎片** | 家人的尺码、药品、偏好散落在脑海和各种 app 里 | 需要时找不到 |

### 1.3 解决方案

通过 AI 将碎片化的生活信息转化为有逻辑的家庭管理决策，降低「家庭管理心智负担」。

**传统工具 vs 生活秘书**：

| 维度 | 日历 + 备忘录 + ChatGPT | 生活秘书 |
|------|------------------------|---------|
| 输入方式 | 手动填表 | **自然对话，秘书自动提取结构化信息** |
| 信息关联 | 孤立条目 | **跨时空自动关联（北京出差 → 老同学 → 天气）** |
| 行动力 | 只提醒 | **先做后说，可撤回的事直接执行** |
| 记忆 | 无 | **持续积累家庭记忆，越用越懂你** |
| 情感 | 冰冷工具 | **懂分寸、有温度、像多年老秘书** |

### 1.4 产品原则

| 原则 | 说明 | 反面 |
|------|------|------|
| **懂分寸** | 适度提醒，不打扰，不制造焦虑 | 每件事都 push 通知 |
| **不填表** | 所有输入通过对话完成，零学习成本 | 让用户填 10 个字段的表单 |
| **会串联** | 自动关联新旧信息，形成知识网络 | 信息孤岛，每次都要从头说 |
| **先做后说** | 可撤回的事直接执行再汇报 | 反复问"要不要我帮您……" |
| **能执行** | 不只提醒，还能帮助落实 | 只说不做的提醒机器 |
| **有温度** | 理解情绪，回忆有故事感，不是冷冰冰的数据 | 像 ERP 系统一样展示家庭数据 |

### 1.5 产品红线

- 不代替决策，只提供建议
- 不主动联系他人，敏感操作需用户确认 (Human-in-the-loop)
- 不滥用数据，仅用于服务用户
- 线上环境严禁返回虚假/mock 数据
- 不做通用 AI 对话工具，专注家庭生活场景

### 1.6 明确不做的事（Anti-Features）

| 不做 | 原因 | 已有替代 |
|------|------|---------|
| **通用 AI 对话** | 偏离定位，用户会拿来写作文、问编程 | ChatGPT / Claude |
| **完整记账** | 需要每笔记录，与"不填表"矛盾 | 随手记、MoneyWiz |
| **深度健康诊断** | 医疗 AI 门槛极高，风险不可控 | 丁香医生、春雨医生 |
| **社交 Feed** | 家庭秘书不是社交产品 | 微信、朋友圈 |
| **日程精确到分钟** | 家庭场景是"哪天"而非"几点几分" | 日历、滴答清单 |
| **企业级协作** | 家庭≠团队，不需要看板/甘特图 | 飞书、Notion |
| **内容创作** | 写文案、做PPT不是家庭秘书的事 | Notion AI、WPS AI |

> **判断标准**：如果一个功能让用户觉得"这是个AI工具"而非"这是我的秘书"，就不做。

## 三、核心交互：对话流即界面

### 3.1 设计理念

**不让用户填表，所有输入通过对话完成。** 用户只需"随口一说"，秘书自动提取结构化信息。

**主入口**：极简聊天界面（支持语音）+ 智能卡片展现关键信息。

```
┌─────────────────────────────────────┐
│                                     │
│  [晨报] 早安！今日 3 个日程         │
│    天气 12°C，建议穿外套            │
│    妈妈生日还有 3 天               │
│    [查看详情] [发送祝福]            │
│                                     │
│         帮我看看下周出差北京要注意啥 │
│                                     │
│  好的，北京出差安排如下：            │
│  ✈️ 行程已建立                      │
│  🍽️ 张明约了周三晚上               │
│  🎁 王总安排在周四，茶叶已备好       │
│  🌡️ 北京零下5度，厚外套已加入提醒   │
│  还有什么要调整的吗？               │
│                                     │
│  ┌──────────────────────┐           │
│  │ 🎙️ 说点什么...       │  [发送]   │
│  └──────────────────────┘           │
└─────────────────────────────────────┘
```

### 3.2 对话流设计

**连续对话流 + 异步推送时间线**：
- 4 小时无对话自动新会话，否则延续上一个 — 用户无需管理会话
- 对话中的实时响应 + 后台异步整理的结果，自然混排在同一条时间线中
- 打开 app 看到的不是空白，而是秘书主动推送的信息（晨报、提醒、价格变动等）
- 跨会话记忆自动提取，"上次那个旅行计划"就能找到

**砍掉的功能**（降低认知负担）：
- ~~会话列表/管理~~ — 家庭场景不需要
- ~~会话标题自动生成~~ — 无列表则无需标题
- ~~编辑历史消息~~ — 直接说新的更自然

### 3.3 秘书工作模式

**核心原则：先做后说，只在关键节点请示。**

| 模式 | 触发 | 秘书行为 | 示例 |
|------|------|---------|------|
| **即时响应** | 用户对话 | 理解 → 关联记忆 → 直接执行 → 汇报 | "安排下周出差" → 自动建行程 |
| **延时整理** | 定时任务 | 扫描 → 发现关联 → 自动处理 → 汇报 | 晨间简报 |
| **洞察推送** | 事件触发 | 生成洞察 → 采取行动 → 告知用户 | 天气变化 → 提醒带伞 |

**什么时候请示，什么时候直接做？**

| 直接做（可撤回） | 需请示（不可撤回） |
|----------------|------------------|
| 设置提醒 | 大额支出（订机票、酒店） |
| 准备资料、查询信息 | 取消已确认的安排 |
| 记录信息 | 敏感信息分享 |
| 调整非关键时间 | 涉及第三方承诺 |

### 4.2 智能对话（The Ear）

**定位**：用户与秘书的唯一交互入口，从自然语言中提取信息、执行任务、给予反馈。

#### 核心能力

| 能力 | 说明 | 示例 |
|------|------|------|
| **意图识别** | 从模糊表述中理解用户需求 | "下次去北京想见老同学" → 存入北京待办池 |
| **情感感知** | 识别对话中的情绪，调整响应方式 | "今天开会被领导批了" → 今晚推荐轻松活动 |
| **记忆提取** | 对话中自动关联相关历史信息 | 提到"妈妈" → 调出健康档案和近期记忆 |
| **模糊时间解析** | 识别"下次""以后""有空时"等非即时需求 | "等天暖和了带孩子去动物园" → 存入春季待办 |
| **多轮上下文** | 连续对话保持上下文，支持追问和修改 | "改到下午" → 知道改的是刚才说的那件事 |

#### 三路路由架构

```
用户输入
    ↓
┌──────────────────────────────────┐
│  意图路由器                        │
│  1. Redis 检测活跃会话 (~1ms)     │
│     → 有热会话? 跳过分类，直走深思考 │
│  2. 若无热会话 → Haiku 两轴分类    │
│     轴1: difficulty (即时/推理)    │
│     轴2: action + enhance         │
└──────────┬───────────────────────┘
           │
     ┌─────┼──────────┐
     ▼     ▼          ▼
  快反射  混合增强     深思考
 (FAST)  (HYBRID)    (SLOW)
  <1s    即时+后台     异步队列
  ~70%    ~10%        ~20%
     │     │  │          │
     │     │  └──后台──→ │
     └─────┼─────────────┘
           ▼
   结果推送（SSE / WebSocket）
```

**三条路径**：

| 路径 | 触发条件 | 处理方式 | 示例 |
|------|---------|---------|------|
| **快反射 (FAST)** | `difficulty=即时` 且不需增强 | Haiku 直接响应，SSE 流式 | "几点了" "今天天气" |
| **混合增强 (HYBRID)** | `difficulty=即时` + `enhance=true` | 快反射**先回答** → 后台 Sonnet **补充关联** | "北京天气" → 即时返回温度 → 后台补充"下周出差记得带厚外套" |
| **深思考 (SLOW)** | `difficulty=推理` 或热会话 | Celery 异步 → Sonnet + MCP 工具 | "帮我规划三亚旅行" |

**混合增强的核心价值**：用户不需要等待深度分析，先得到快速答案，几秒后收到"秘书追加的贴心提醒"——这正是"懂分寸"的体现。

**HYBRID 触发场景**：

| 场景 | 快反射返回 | 后台增强追加 |
|------|----------|------------|
| 天气查询 + 出差关联 | "北京-3°C，晴" | "下周出差带厚外套，张明约了周三晚餐" |
| 日程查询 + 智能建议 | "明天有3个会议" | "14点和16点的会冲突，建议推迟16点那个" |
| 设提醒 + 上下文补充 | "已设提醒" | "顺便说，妈妈生日也在下周，要提前准备吗？" |

**频率控制**：每个 topic 有 30 分钟冷却期，防止过度增强打扰用户。

**热会话优化**：检测到活跃 SDK 会话时，跳过 Haiku 分类直接走深思考 → 保持对话连贯性，节省一次 API 调用。

#### 交互场景示例

**场景：从抱怨到解决**

```
用户: "老婆说净水器滤芯到期了，但我下周要去上海，真烦"

秘书处理:
├── 提取: 物体=净水器滤芯, 动作=更换, 情绪=焦虑
├── 检索: 历史记录找到型号 小米H600
├── 规划: 后天送达，出差前可完成
↓
秘书: "老板别烦，滤芯型号是小米H600，京东链接已备好，
      预计后天到家，到时提醒你5分钟搞定。"
```

**场景：碎片信息自动关联**

```
用户: "下次去北京想见老同学李思远"

秘书处理:
├── 提取: 人物=李思远(旧友), 地点=北京, 触发条件=下次去北京
├── 存入: 北京·长效待办池，建立 李思远↔北京 关联
↓
（两周后用户说"下周出差北京"）

秘书: "对了，上次你说想见李思远，5年没联系了。
      要我帮你约周三晚上吗？"
```

### 4.3 家庭看板（The Dashboard）

**定位**：家庭待办中心 — "有什么重要的事别忘了？有什么要提前准备的？"

#### 设计哲学

家庭生活不是会议日程。用户打开看板的心理模型不是"看 timeline 排了什么"，而是：

> "最近有什么重要的事？有什么要提前准备的？有什么不能忘的？"

| 维度 | 工作日程 | 家庭生活 |
|------|----------|----------|
| 时间粒度 | 几点几分 | 哪天/哪周 |
| 核心驱动 | 准时到场 | **别忘了、要准备** |
| 情感属性 | 低（完成任务） | **高（亲情、回忆、期待）** |

- **月内安排**：7-30 天，按日紧凑列表
- **更远**：30 天以后，折叠区

- **关联记忆片段**：卡片带出对话中提到的相关回忆

## 五、扩展功能模块（下一步）

### 5.1 重要日期管理

**核心**：永远不忘记任何重要日子。

- 关联推荐：生日提醒附带礼物建议，节日提醒附带准备清单

**核心**：建立完整的家庭知识库。

信息来源：
- **对话积累**（主要）：日常对话中自动提取和归类
- **主动补充**（辅助）：用户在需要时补充特定信息
- **照片识别**（增强）：处方单、接种证、证件的 OCR

信息类型：
- 基本信息：姓名、生日、关系

- 健康信息：过敏源、慢性病、用药

**核心**：维护人情世故，不欠人情债。

- 兴趣班：时间管理 + 接送提醒 + 进度记录
- 成长报告：年度自动生成，可作为礼物

## 六、远期愿景模块

### 6.1 随身硬件

**概念**：随身佩戴的 AI 助手设备，补充手机交互的不足。

**核心场景**：
- 语音随时录入："记一下，老婆说想去日本"
- 免打扰检查：会议中手腕震动提醒"下午 3 点接孩子"
- 紧急通知：家人紧急联系时的强提醒

**形态选择**（待验证）：
- 智能手表/手环（低成本，生态成熟）
- 挂坠/胸针（差异化，但市场教育成本高）
- 家庭 Hub（智能音箱形态，适合家庭共用场景）

**设计原则**：
- 硬件只是"信息捕获 + 轻量提醒"的补充入口
- 复杂交互仍在手机 App 完成
- 不做独立运算，依赖云端 AI

**行业教训**：
- Humane AI Pin 和 Rabbit R1 的失败告诉我们：硬件不能替代手机，只能补充手机
- 硬件最大价值 = 降低"随口记一下"的摩擦力

### 6.2 健康管理

以家庭为单位的健康档案管理：
- 老人用药提醒和复诊跟踪
- 孩子体检和疫苗（与成长记录整合）
- 体检报告解读和异常预警
- **注意**：不做诊断，只做信息管理和提醒

### 6.3 家务与生活

- 家庭维修/保养日历（滤芯、空调清洗等）
- 采购清单（自然对话添加，智能分类）
- 家政服务预约
- **定位**：轻量提醒，不做深度管理（深度需求有专业 app）

### 6.4 财务概览

- 红包往来记录（人情管理延伸）
- 固定支出提醒（房贷、保险、学费）
- 大额支出决策辅助
- **注意**：不做完整记账（随手记等专业 app 已很成熟），只做与家庭事务相关的财务提醒

## 八、秘书整理机制（Curation）

### 8.1 整理触发时机

| 类型 | 触发 | 时延 | 示例 |
|------|------|------|------|
| **即时整理** | 用户对话 | <3 秒 | "安排下周出差" → 立即分析关联 |
| **定期整理** | 定时任务 | 定时 | 晨报/午间/晚间/周报 |
| **事件触发** | 外部变化 | 准实时 | 天气预警 → 关联受影响行程 |
| **洞察生成** | 数据分析 | 后台 | "已经3个月没联系张明了" |

### 8.2 整理工作流

```
Step 1: 信息收集
  对话输入 + 外部数据(天气/日历) + 历史记忆
           ↓
Step 2: 理解分析
  意图识别 → 实体抽取 → 上下文关联 → 时间解析 → 优先级判断
           ↓
Step 3: 关联发现
  人物匹配 → 地点匹配 → 历史事件 → 人情记录 → 潜在冲突
           ↓
Step 4: 方案生成
  主事件构建 → 关联事项附加 → 提醒生成 → 建议准备
           ↓
Step 5: 执行 + 汇报
  可撤回 → 直接执行再汇报
  不可撤回 → 先请示再执行
```

### 8.3 洞察类型

| 类型 | 触发条件 | 示例 |
|------|---------|------|
| 时间洞察 | 事件临近/超时 | "明天的会议还没准备资料" |
| 关系洞察 | 长期未联系 | "李总已经3个月没联系了" |
| 人情洞察 | 人情未还 | "王总的人情还没还，他下周生日" |
| 记忆洞察 | 历史承诺 | "你说过要给妈妈买按摩椅" |
| 准备洞察 | 事项未就绪 | "三亚行还有3项没准备" |

### 10.3 关键技术决策

## 十三、风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| **LLM 幻觉** | 家庭信息出错后果严重 | RAG 检索 + 事实核查 + 关键信息用户确认 |
| **隐私泄露** | 家庭数据极敏感 | 端到端加密 + 最小数据原则 + 本地优先存储 |
| **过度打扰** | 用户关闭通知 → 流失 | 智能静默策略 + 重要性评分 + 用户可控频率 |
| **冷启动** | 新用户无数据无价值感 | 渐进式引导 + 5分钟首次价值体验 + 日历导入 |
| **LLM 成本** | 高频用户成本不可控 | Haiku/Sonnet 分级 + 缓存 + 本地推理探索 |
| **用户获取** | 需要输入大量信息才有效 | 对话式积累（不填表）+ 逐步发现价值 |
| **竞品替代** | Apple/Google 内置 AI | 深耕"家庭记忆"差异化 + 中国本地化场景 |
| **硬件失败** | 参考 Humane Pin | 先验证软件价值，硬件作为增强而非核心 |

## 十四、竞争分析与差异化

### 14.1 竞争格局

| 竞品 | 优势 | 劣势 | 我们的差异 |
|------|------|------|-----------|
| **Apple Reminders + Calendar** | 系统级集成，免费 | 无记忆，无关联，不智能 | 我们有跨时空关联和家庭记忆 |
| **ChatGPT / Claude** | 通用 AI 能力强 | 无持久家庭记忆，无主动推送 | 我们专注家庭场景，有结构化记忆 |
| **滴答清单 / Todoist** | 任务管理专业 | 手动输入，无 AI 关联 | 我们是对话式输入 + AI 自动整理 |
| **小爱同学 / 天猫精灵** | 语音交互，硬件生态 | 无深度记忆，以控制为主 | 我们是深度理解的秘书，不是语音控制器 |
| **Apple Intelligence** | OS 级整合 | 通用化，非家庭专属 | 我们深耕家庭垂直场景 |

### 14.2 核心差异化（三把尖刀）

**一句话价值主张：帮你管人情、不忘事。**

1. **人情 AI** — 做中国人的社交关系助手
   - 人情账本（收支平衡可视化）+ 送礼去重 + 节日批量规划 + 关系健康度
   - **为什么是护城河**：Apple/Google 不会深耕中国人情文化；ChatGPT 没有持久关系记忆
   - **验证方式**：春节红包场景（1 月集中需求），验证 PMF

2. **执行秘书** — 从"提醒你做"到"帮你做了"
   - 碎片信息 → 结构化 → 自动执行（可撤回的先做后说）
   - **为什么是护城河**：日历/Todoist 只能提醒；ChatGPT 没有执行能力；需要深度家庭上下文才能"做对"
   - **当前缺口**：执行闭环尚不完整，"先做后说"能力需从查询扩展到真正的 Agent 执行（下单、预约、发送）

3. **时光胶囊** — 家庭记忆的情感价值
   - 那年今日 + 故事聚合 + 年度回顾 + 成长记录
   - **为什么是护城河**：记忆是时间积累的资产，迁移成本极高 —— "换一个 app 意味着失去所有家庭记忆"
   - **情感锁定**：用户不会因为竞品便宜 5 块钱就抛弃 3 年的家庭记忆

### 14.3 竞争时间窗口

**关键判断：Apple Intelligence 预计 18 个月内将家庭场景整合到 iOS 原生体验中。**

| 时间 | 我们 | Apple |
|------|------|-------|
| 现在 | V1.0 已完成，核心链路打通 | 通用 AI，未针对家庭 |
| +6 月 | V1.5 人情+档案+日期，形成差异 | 可能发布家庭相关 feature |
| +12 月 | V2.0 执行闭环，用户记忆积累 | Siri 可能支持家庭记忆 |
| +18 月 | V3.0 硬件+深度绑定 | 系统级整合可能上线 |

**应对策略**：
- **前 12 个月**：疯狂积累用户的家庭记忆数据 — 这是 Apple 无法追赶的
- **差异化锁定**：人情管理（Apple 不会做）+ 中国节日/文化场景（Apple 不擅长）
- **时光胶囊效应**：用户记忆越多，迁移成本越高，12 个月后自然形成壁垒

**¥29/月标准版将亏损。** 应对策略：

| 策略 | 预期节省 | 优先级 |

| **家庭版 ¥49 作为利润中心** | +¥20/家庭 | P0 — 功能差异化拉动升级 |

**盈亏平衡点**：标准版 + 家庭版混合，需家庭版占比 > 30% 才能整体盈利。

| **事件图谱** | 以行程/事件为中心的关联关系可视化 |
| **语义看板** | 按语义维度（本周重点/需要准备/月内安排）分组，替代传统日历排列 |
| **Memory Lane** | 回忆长廊，以故事为单位的历史事件展示 |
