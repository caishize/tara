子扫描器扫描的表SQL 条件判断逻辑输出
1. 日期临近
_scan_approaching_dates()		 important_dates WHERE family_id=? AND solar_date >= TODAY AND solar_date <= TODAY+90d
ORDER BY solar_date ASC LIMIT 20		 每条日期: days_until = (solar_date - today).days
过滤: days_until ≤ preparation_lead_days
排除: 已有非 placeholder CuratedEvent 的日期
优先级: days≤3 → P1; 亲密成员+days≤7 → P0; 其他 → P2 		ProactiveTrigger(type="approaching_date", data={date_id, title, date_type, solar_date, days_until})
2. 冷关系
_scan_cold_relationships()		 members
+ RelationshipThermometer		 WHERE family_id=? AND is_deleted=false LIMIT 50
每成员调用 compute_temperature()		 计算温度状态 → 过滤 status ∈ {cold, frozen}
优先级: frozen → P1; cold → P2 		ProactiveTrigger(type="cold_relationship", data={member_name, temperature_status, composite_score})
3. 过期承诺
_scan_stale_commitments()		 commitment_records WHERE family_id=? AND status='pending' AND commitment_type IN ('vague','conditional') AND next_follow_up_at <= NOW()
ORDER BY next_follow_up_at LIMIT 20		 days_overdue = (now - next_follow_up_at).days
优先级: days_overdue ≥ 7 → P1; 其他 → P2 		ProactiveTrigger(type="stale_commitment", data={commitment_id, who, what, to_whom, days_overdue})
4. 用户节奏
_scan_user_rhythm()		 conversation_messages
+ assistant_chat_sessions		 WHERE role='user' AND created_at >= NOW()-14d
GROUP BY EXTRACT(HOUR FROM created_at)
HAVING count ≥ 3 ORDER BY count DESC LIMIT 2		 取 top-2 峰值小时 (14 天回看)
检查: 当前 UTC 时 ≥ peak_hour+1 且今天该时段无用户消息?
若是 → 发出 check-in 提醒 		ProactiveTrigger(type="user_rhythm", priority=P3, data={peak_hour_utc, messages_at_peak})
合成逻辑：当 2+ 个触发指向同一个 target_member_id 时，合并为 family_focus 触发，priority 取最高值。Narrative 用模板拼接 (无 LLM)。
后续 dispatch：approaching_date → 场景 ⑥；cold_relationship/stale_commitment → 作为候选参与下次 06:00 生成；user_rhythm → P3 低优先推送。
